# v0.5 AI Provider 与一次性回复说明

## 当前目标

* 接入真实 AI 能力，但保持低频、手动、克制。
* 当前只做一次性 AI 陪伴回复，不做聊天系统。
* AI 能力服务于桌宠陪伴和专注辅助，不替代主流程。

## 支持的 Provider

* OpenAI-compatible。
* DeepSeek 推荐配置。

## DeepSeek 配置示例

```text
provider: openai-compatible
baseUrl: https://api.deepseek.com
model: deepseek-v4-flash
apiKey: 用户自己的 key
```

AI 设置区域的“使用 DeepSeek 推荐配置”只会填入 provider、baseUrl 和 model 草稿，不会覆盖 API Key，不会自动保存，也不会发起请求。

## 请求触发条件

* 用户点击发送才请求。
* AI 对话开关已开启。
* Provider 为 `openai-compatible`。
* baseUrl、apiKey、model 配置完整。
* 输入内容非空。

## 请求格式

请求使用 OpenAI-compatible Chat Completions 格式：

```text
POST {baseUrl}/chat/completions
Authorization: Bearer {apiKey}
Content-Type: application/json
```

当前不启用 `stream`。

## 请求内容边界

发送：

* 用户输入。
* 今日专注轮数。
* 今日累计分钟。
* 最近状态标签，最多 3 个。
* 最近一条本地记忆 text。

不发送：

* 完整 `companionMemory`。
* 完整 notes。
* 完整今日记录。
* API Key 到日志。
* `localStorage` 全量内容。

## 隐私边界

* API Key 保存在本地 `localStorage` 的 `focusPet.aiSettings`。
* 请求直接发送到用户配置的 `baseUrl`。
* 当前没有后端中转。
* 不保存聊天历史。
* 用户不点击发送就不会请求 AI。

## 错误处理

* API Key 错误。
* 模型或地址错误。
* 频率限制。
* 网络失败。
* 请求超时。
* 返回格式异常。

错误提示应保持温和简短，不显示原始堆栈、API Key 或完整请求内容。

## 当前不做

* 多轮聊天。
* 消息流。
* 聊天历史保存。
* 流式输出。
* 主动对话。
* 后台请求。
* 专注中 AI 对话框。
* 专注完成后自动 AI 总结。
* 状态标签后自动 AI 回复。

## 后续可能方向

* v0.6 再考虑多轮聊天，但必须可关闭、低干扰。
* v0.6 再考虑更完整的上下文管理。
* 主动陪伴必须谨慎，不能打扰专注。
